## Changes

- Apply/clear/type changes refresh checkout totals immediately; invalid/nonfinite discounts and percentages above 100 are rejected.
- Reset clears discount/reason, note fields, backdate/date/time and payment selection. Unresolved recovery keeps the basket; verified recovery resets it.
- Pending/recovery state disables controls and guards mutation handlers, including another tab's pending journal. A completed sale in another tab no longer clears an unrelated unsent basket.
- Receipt pickup, note, discount metadata and grouped lines come from the same pre-await snapshot as the submitted request. Atomic sale client, journal, receipt verification and transport remain unchanged.
- Order history uses DOM/textContent, with no interpolated inline order actions. Legacy cancel writes are removed; mobile explains that refunds must use the supported main-web orders page. This candidate does not implement a new mobile refund flow.
- Loading/error/offline/empty menu states and retry preserve the basket; checkout remains blocked before a valid menu snapshot. Read-only shared menu-insights ranking uses existing semantics and freezes after interaction. Recommended items are labelled ร้านแนะนำ.
- Zoom is enabled, quantity targets are at least 44px, small-screen product cards use two rows, short screens compact the header, dialogs scroll, cart is keyboard-operable, dialogs trap/return focus and support Escape. Offscreen images are lazy loaded.

## QA follow-up candidate — 21 November 2026

Supersedes the initial candidate above. New SHA-256: `679d853b7b920ad7b73afbd24653b4a4b2f6126dd38ce326a1c1fd3318f1ba38`.

- A page records the receipt ID and basket fingerprint only when it submits its own sale. Verified recovery/storage notification clears only that matching owned basket. Other tabs retain their unsent baskets. Ownership is intentionally not restored on reload: a fresh page may recover the shared journal without claiming another page's basket.
- Read-only menu loading is permitted while a journal is pending; transaction controls remain locked. Reload → recover → add a new item works without a second reload.
- Every menu refresh sets readiness false; errors retain basket/displayed menu but block checkout until successful validation. Explicitly inactive categories/products are excluded.
- Category tabs use textContent and bound listeners, including hostile names/IDs.
- Dashboard menu/category/customer renderers now exist and use safe DOM. When the external chart library is unavailable, daily numbers are shown with an explicit graph-load failure label instead of throwing ReferenceError. This is a data fallback, not evidence that the CDN chart library rendered.

Follow-up validation: existing 223/223 regressions; expanded 15-group synthetic Chrome harness; actual same-context two-page localStorage/Web Locks test adapted from QA's independent reproduction. It asserts B retains its basket after recovery and A can reload pending, recover and start another bill. All sales/acknowledgements are synthetic, with three mock committed sales and no real backend traffic. The Dashboard navigation also loads a valid synthetic RPC report.
